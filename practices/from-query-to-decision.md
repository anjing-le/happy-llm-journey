# 从能查数到决策链

围绕 AI 问数，逐步建设查询、语义准确性、数据复用与决策执行能力。来自个人实践经验，具体效果与验证范围待补充。

## 核心思路

**能查数 → 能查准 → 能用数 → 决策链**。四种能力持续积累，后者不替代前者；按业务需要推进。

## 怎么做

- **能查数**：先接入实际需要的数据源，将查询执行与上层业务理解分开，按需扩展多源适配。
- **能查准**：整理指标口径、表字段语义、数据粒度和关联条件。原文采用表字段关系图辅助查询，关系须经过数据核验与业务确认。
- **能用数**：需要多步分析时，将问数作为 Harness / Loop 下的专业能力，为后续分析提供数据、口径和来源。
- **决策链**：按授权范围形成建议或执行动作，再用执行结果检验效果，持续调整。
- **降低维护成本**：让 AI 通过明确的工具参与表和指标的设计维护；由专家确认关键口径，用已核验的参考结果做回归评测。
- **让结果可校对**：把实际执行的 SQL 解释成业务语言，说明统计口径、时间范围和筛选条件，同时保留结果校验。

## 适用与限制

适用于需要复杂业务查询、复用数据分析能力，或探索经营决策闭环的团队。

图数据库、多专家协作和 AI 维护数据引擎是本文讨论的实现选择，不是所有问数系统的必选项。SQL 能执行、业务解释合理，都不等于结果正确；写入和经营动作应有相应的权限、验证与回退安排。

原文提供经验、架构思路和示例，未附可复现评测数据，不据此承诺准确率或维护成本收益。
