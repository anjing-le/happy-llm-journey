# 第一期 · 从 agent 开发学会 llm 所有

## 活动目标

选择一个具体任务，做出能运行、能解释、能验证的 Agent，在实践中逐步建立 LLM 应用的知识地图。

主干结构已确定，具体题目、推荐方法和知识条目逐步补充。活动名称表达学习愿景；完成标准以明确的任务和验收范围为准，不以覆盖全部 LLM 知识为承诺。

## 两条内容线

- **应用主线**：围绕同一个 Agent，学习下面六个部分。重点是理解、选择和验证，不要求给一个项目装上所有机制。
- **模型适配扩展**：当评估发现现有模型与应用侧改进仍不足时，再研究是否需要改变模型。该扩展可独立学习，不是完成应用主线的前置条件。

## 应用主线：六个部分

| 部分 | 学习范围 | 在项目中需要说明或验证什么 |
| --- | --- | --- |
| 基础与核心循环 | 任务与验收；消息、Token、采样、结构化输出、流式响应；模型、上下文和工具如何形成循环；何时不需要 Agent | 跑通最小任务，能解释输入、决策、工具结果回填、结束条件与失败情况 |
| 组织与任务编排 | 固定工作流与自主决策；顺序、路由、并行；任务拆分、交接和汇总；单 Agent 与多 Agent 的取舍 | 说明采用何种组织方式及原因；只有任务确实需要时才引入多 Agent |
| 上下文工程 | 指令、历史、状态、记忆与业务事实；数据解析、清洗、切片、索引、更新；检索、按需读取、筛选与压缩 | 能追溯一次任务使用了什么信息、来自哪里、为什么采用；检验缺失、过期和无依据场景 |
| 工具与扩展机制 | 工具描述、参数、结果、错误；参数校验、权限和副作用；文件、Shell、搜索、业务 API；按需理解 MCP、Skill、Hook 等机制 | 工具可验证，错误可识别，关键副作用受控；不要求每种工具与扩展形式都接入 |
| Harness 与运行保障 | 驱动循环、状态保存与恢复；超时、取消、重试、幂等；隔离、审批与权限；应用交互、部署运行、并发、限流与成本 | 能观察任务进度，演示受控失败、恢复或终止，说明执行边界与资源约束 |
| 评估、观测与改进（Evals） | 任务成功标准、代表性样本、失败与边界用例；程序检查、模型评分与人工判断；追踪结果、过程、延迟和成本 | 用证据判断任务是否完成，定位失败环节，改进后做回归比较 |

身份权限、数据隔离和不可信输入处理贯穿相关环节。评估从最初定义任务时开始，不留到项目末尾才补。

## 推荐实践顺序

明确任务与验收 → 跑通最小调用和核心循环 → 按需补上下文与工具 → 验证失败场景 → 完善运行保障 → 按需增加编排 → 持续评估与改进。

六个部分是学习范围，不是必须逐个堆功能的步骤。每个部分都应能解释在当前项目中的选择；不适用的机制说明理由即可。

## 模型适配扩展

学习范围：训练数据与数据划分、微调与 LoRA 等适配方式、偏好优化、模型评估、部署接入及版本管理。具体主题后续逐项整理，不提前生成知识正文。

- 先根据任务失败证据判断问题来自数据、上下文、工具、流程还是模型能力；不是默认用微调解决一切。
- 与应用主线通过模型输入输出约定、工具调用及结构化输出能力、应用评估集连接。
- 替换模型后验证接口和行为兼容性，对比任务效果、成本、延迟与退化；接口一致不代表效果一致。
- 模型与算法原理放入[算法](../../knowledge/algorithms/README.md)，部署、接入和运行实现放入[工程](../../knowledge/engineering/README.md)，活动只串联学习路径。

## 阶段交付

围绕所选题目提交可复现的 Agent、关键取舍说明、任务与失败场景的验证证据、遗留问题和复盘。各题具体标准随题面确定。模型适配作为选修扩展另设比较实验，不阻塞应用主线完成。
