# 第二期 · 一个人如何做好 vibe coding

用 AI 协作完成一个真实可运行、可验证、能解释的项目：从理解目标到交付，再通过返工和需求变化检验自己的判断。

> 状态：材料整理中，题面为公开草案。沿用此前 AI-Coding 活动设计；正式时间、参与方式和最终题目安排尚未确定。

## 从哪里开始

1. 阅读[活动流程](docs/WORKFLOW.md)和[内容边界](docs/BOUNDARIES.md)。
2. 从[七道项目题](assignments/README.md)中选择一个背景。
3. 按[作业装配说明](docs/PACKAGING.md)准备自己的仓库。
4. 使用[学员模板](templates/student-repo/README.md)和[阶段提示词](templates/student-repo/prompts/00-start.md)推进。
5. 提交运行证据，经历评审、返工、临时变更与复盘。

## 一个完整实践过程

理解目标 → 澄清与规划 → 开发与验证 → GitHub 交付 → 预审与返工 → 演示与追问 → 临时变更 → 复盘。

此前活动设计以约 7–14 天为一个项目周期，各题规模不同，以题面及最终活动安排为准。AI 可以辅助分析、实现和检查；参与者需要作出取舍、核验结果，并能独立解释关键实现。

## 与知识、实践方法的关系

遇到不懂的概念，回到[知识底座](../../knowledge/README.md)检索；选择做法时参考[实践方法](../../practices/README.md)。这两个模块目前仍在建设，本期保留既有阶段指导，尚未完成逐项关联。

实践中的困难既可能来自知识缺口，也可能来自方法或题目设计。复盘用于补充知识、修正方法，不只评价参与者。
