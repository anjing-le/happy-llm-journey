# 活动总体设计

## 目标

通过一个明确的活动目标和可选择的题目，让参与者运用推荐的最佳实践完成任务，在过程中按需学习知识，并通过交付与反馈改进理解和方法。

活动不是另一套独立知识库。不同题目可以共用方法，不同方法可以引用同一份知识。

## 参与路径

活动目标 → 选择题目 → 按推荐方法实践 → 按需查知识 → 交付与验证 → 反馈改进。

1. **明确总体目标**：说明活动希望帮助参与者获得什么能力、完成什么结果。
2. **选择一道题目**：提供可选背景；每道题明确目标、范围、交付物和验收标准。参与者选择其中一道，不要求完成全部题目。
3. **按推荐方法实践**：在关键步骤链接相应最佳实践，帮助参与者推进、判断和验证。方法是参考，允许基于具体情况说明取舍。
4. **按需查知识**：遇到不理解的概念或原理，沿链接进入知识底座，理解后返回当前任务继续实践。
5. **交付与验证**：提交能对应验收标准的成果与证据，能够解释关键决策；不只判断是否遵循了推荐步骤。
6. **反馈改进**：区分知识缺口、方法不适用、题目不清楚和执行问题，据此改进相应内容。

## 三个模块的关系

| 模块 | 维护内容 | 如何关联 |
| --- | --- | --- |
| [活动](README.md) | 总体目标、题目、实践路径、交付与验收 | 在需要做决策和采取行动的位置链接方法，在知识缺口处链接知识 |
| [最佳实践](../practices/README.md) | 我们归纳的方法、判断依据、适用条件与验证证据 | 链接支撑方法的知识，以及用来检验方法的实践案例 |
| [知识底座](../knowledge/README.md) | 关键概念、原理、理解、来源与案例 | 解释是什么、为什么，并链接相关方法与活动 |

同一份知识或方法保持一个维护来源，通过 Markdown 相对链接复用，不为每期活动复制整套内容。链接应尽量到具体内容；当前缺失的内容标明待建设，不用空链接伪装成已完成。

## 内容组织与迭代

- 各模块 README 是总体说明与导航，每期活动 README 是该期的入口。
- 优先使用「模块总览 → 主题或活动 → 具体内容」的浅层组织；简单主题直接使用一个 Markdown 文件，不为整齐而增加目录。
- 新内容须从对应入口能找到，并提供返回上级或相关内容的链接。
- 知识当前仅分工程、算法，先在各自 README 下用列表连接具体内容；最佳实践先用列表积累，成体系后再讨论提取文件夹。不将三期活动直接当作知识分类。
- 活动可以引用持续更新的知识与方法；正式发出的题面和验收标准需要记录版本，避免进行中的任务标准悄悄变化。
- 迭代先明确问题发生在哪个模块，再修改对应来源，检查受影响的活动和链接。
