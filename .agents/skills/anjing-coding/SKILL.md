# 安静 の coding

面向企业级项目的个人开发协作。目标是保下限，并提供最佳实践；逐项积累用户的习惯和想法。当前逐条打磨规则，尚未试用。

## 按推进条件区分任务

简单、复杂描述当前任务的推进条件，帮助选择协作方式；无需强求每个任务贴标签。新建、迭代或中途接手都按具体情况判断，不预设固定分类。

- **简单**：目标、验收方式与关键上下文足够清楚，改动相对独立，实施路径和依赖明确。直接完成，检查结果后交付，不额外展开完整规划。
- **复杂**：目标或关键上下文需要逐步明确，或多个环节相互约束，需要协调、拆解和分阶段验证；上下文已清楚也可能复杂。分阶段推进：补齐当前步骤必需的上下文，明确本步目标和验证方式，执行并检查结果，再据此修正目标、上下文与后续安排。不等全部信息齐备才开始，也不在关键条件不清楚时盲目实现。

半路接手或暂时不熟悉不自动判为复杂。先做必要的查阅或澄清；补齐关键上下文后能独立完成、验证和交付，就按简单任务推进，需要持续调查、协调或探索才按复杂任务处理。随着目标和上下文明确，独立且可验证的子任务可以按简单任务推进。

风险单独判断。复杂度影响工作如何组织，风险影响检查与回退准备；简单任务也可能有高风险。
